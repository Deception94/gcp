# Secure Finance Portal — Web Application Security Lab

An educational finance-tracker web app built to demonstrate practical web application security controls using Flask and SQLite.

## Security controls demonstrated
- Password hashing and verification
- Session renewal after login
- CSRF tokens for state-changing POST requests
- Parameterized SQL queries
- Server-side validation of amounts and descriptions
- Per-user transaction isolation and ownership checks
- HTML output escaping through Jinja templates
- Security response headers and minimal audit logging
- Automated security regression tests

## Run locally
Python 3.10+ required.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Open http://127.0.0.1:5000.

## Demo accounts
- alice@example.com / AliceDemo!23
- bob@example.com / BobDemoPass!23

These are intentionally public classroom demo credentials. Never reuse them for any other service.

## Run tests
```bash
python -m unittest -v test_security.py
```

## Suggested demo
1. Sign in as Alice and add a transaction.
2. Sign out and sign in as Bob; Alice's transaction should not be visible.
3. Try a negative amount; server-side validation should reject it.
4. Run the tests to demonstrate password verification, CSRF enforcement, user isolation, POST-only logout, and security headers.

## Architecture
Browser → Flask routes and validation → SQLite database. Transactions are associated with an authenticated user ID, and ownership is checked server-side for reads and mutations.

## Educational use
Do not use real financial data. Test only this application or systems for which you have permission.


## Deploy publicly for Assignment 4 (Render)

This repository includes a `render.yaml` Blueprint for a classroom demo deployment.

1. Sign in to Render and choose **New → Blueprint**.
2. Connect the GitHub repository `Deception94/gcp` and select the branch containing `render.yaml`.
3. Review the Blueprint configuration. Render generates `PORTAL_SECRET_KEY`; do not replace it with a committed secret.
4. Create/deploy the Blueprint and wait for the build and deploy status to report success.
5. Open the `onrender.com` URL shown by Render and confirm the login page loads. The login screen displays the fictional demo credentials for the reviewer.

The hosted demo uses fictional records and public classroom demo credentials. Do not enter real financial or personal data. The free hosting filesystem is ephemeral: SQLite demo transactions can be cleared when the service restarts, redeploys, or spins down. This is not a production banking application. For production use, replace SQLite with a managed database and conduct a full security review.

### Deployment settings

- Runtime: Python
- Build command: `pip install -r requirements.txt`
- Start command: `gunicorn --workers 1 --threads 4 --timeout 60 app:app`
- Health check path: `/`
- `APP_ENV=production` enables secure session cookies and HSTS.
- `PORTAL_SECRET_KEY` is generated by Render.
- `PORTAL_DB=/tmp/finance_demo.db` keeps the demo database on the ephemeral filesystem.
